Chapter 1

Introduction

1.1 Introduction

Software Quality Assurance (SQA) represents a foundational discipline in computer science and software engineering. It encompasses a structured, planned set of actions designed to ensure that software products strictly conform to established requirements, architectural standards, and security specifications. In complex web engineering projects, modern single-page frontend applications (SPA) communicate continuously with backend REST APIs. Small inconsistencies in parameter formatting, state asynchronous updates, or token signing can cause silent system failures, security vulnerabilities, or data loss.

In this lab project, I performed an end-to-end Software Quality Assurance audit, static code walkthrough, defect discovery analysis, production-grade code remediation, and verification testing on the Conduit RealWorld Application repository. Conduit is a production-grade fullstack web application modeled after Medium. It utilizes React 18 for the user interface, Node.js and Express.js for REST API controllers, and Sequelize ORM backed by PostgreSQL for database storage. Through systematic exploratory and static analysis testing, I uncovered 5 genuine, non-trivial software defects across authentication, parameter parsing, promise handling, form validation, and rendering security. I subsequently implemented direct code-level remedies in the repository for two high-priority defects and verified their resolution.

1.2 Design Goals/Objective

The primary objectives of this lab project are structured as follows:

  • Systematic QA Audit: Conduct exploratory, boundary, security, and state-transition testing across frontend UI components and backend REST endpoints.
  • Defect Cataloging & Logging: Identify and document 5 non-trivial defects in a standard Master Defect Log, detailing defect ID, title, severity, priority, environment, steps to reproduce, expected vs. actual outcomes, and proof-of-defect notes.
  • Code Remediation: Implement clean, production-ready source code fixes directly within the workspace files for 2 target defects (JWT authentication token signing and URL query string ampersand formatting).
  • Verification & Regression Testing: Execute automated unit tests (using Vitest) and manual inspection procedures to ensure zero regressions in adjacent application modules.
  • Academic Deliverable Generation: Package complete project findings, code diffs, presentation slides, and formal documentation matching the CSE Department standards of Green University of Bangladesh.

2.3 Code Remediation & Implementation Walkthrough

I selected two high-priority defects—BUG-01 (JWT Authentication Defect) and BUG-03 (Malformed Query String Ampersands)—to apply direct code-level fixes in the repository source code.

2.3.1 Remediation of BUG-01: JWT Authentication Claim Defect

Root Cause Analysis: In backend/controllers/users.js, the user login handler signIn contained a critical flaw on line 51:

// BEFORE REMEDIATION (users.js)
const { user } = req.body; // user contains only { email, password }
...
existentUser.dataValues.token = await jwtSign(user);

The utility function jwtSign(payload) in backend/helper/jwt.js signs tokens using payload.username and payload.email. Because user was passed directly from req.body.user (which lacks the username property), the signed token payload evaluated to { username: undefined, email: "user@example.com" }. This broke user authorization on all subsequent protected API requests.

Code Fix Applied: I changed the argument passed to jwtSign from user to existentUser (the Sequelize model instance fetched from PostgreSQL).

+++ b/backend/controllers/users.js
@@ -48,7 +48,7 @@ const signIn = async (req, res, next) => {
     const pwd = await bcryptCompare(user.password, existentUser.password);
     if (!pwd) throw new ValidationError("Wrong email/password combination");
 
-    existentUser.dataValues.token = await jwtSign(user);
+    existentUser.dataValues.token = await jwtSign(existentUser);

2.3.2 Remediation of BUG-03: Malformed Query String Ampersands

Root Cause Analysis: In frontend/src/services/getArticles.js, the API client formatted HTTP GET request query strings using double ampersands (&&) instead of single ampersands (&):

// BEFORE REMEDIATION (getArticles.js)
const url = {
  favorites: `api/articles?favorited=${username}&&limit=${limit}&&offset=${page}`,
  feed: `api/articles/feed?limit=${limit}&&offset=${page}`,
  global: `api/articles?limit=${limit}&&offset=${page}`,
  ...
};

Standard HTTP URI specifications (RFC 3986) mandate single ampersand delimiters. The use of && caused the Express HTTP query parser to parse keys with leading ampersands (e.g. req.query['&limit'] and req.query['&offset']). Consequently, backend controller logic evaluating req.query.limit returned undefined, reverting pagination offset calculations to 0 and breaking tag filters.

Code Fix Applied: I replaced all double ampersands (&&) with standard single ampersands (&) across all route keys in getArticles.js.

--- a/frontend/src/services/getArticles.js
+++ b/frontend/src/services/getArticles.js
@@ -7,9 +7,9 @@ async function getArticles({ headers, limit = 3, location, page = 0, tagName, us
     const url = {
-      favorites: `api/articles?favorited=${username}&&limit=${limit}&&offset=${page}`,
-      feed: `api/articles/feed?limit=${limit}&&offset=${page}`,
-      global: `api/articles?limit=${limit}&&offset=${page}`,
-      profile: `api/articles?author=${username}&&limit=${limit}&&offset=${page}`,
-      tag: `api/articles?tag=${tagName}&&limit=${limit}&&offset=${page}`,
+      favorites: `api/articles?favorited=${username}&limit=${limit}&offset=${page}`,
+      feed: `api/articles/feed?limit=${limit}&offset=${page}`,
+      global: `api/articles?limit=${limit}&offset=${page}`,

Chapter 3

Performance Evaluation

3.1 Testing Environment & Verification Procedure

To verify that the code remediations resolved the identified defects without introducing regressions into adjacent modules, I set up a local verification test environment using Node.js v18, React 18, and Vitest test runner.

Verification Procedures Executed:

  1. JWT Claim Verification (BUG-01): Issued HTTP POST sign-in requests to /api/users/login with registered user credentials. Decoded the returned JWT token string using jwt.decode() and inspected claim values.
  2. API Query Parameter Parsing Verification (BUG-03): Inspected outgoing HTTP packets in Chrome DevTools Network tab while navigating through article feeds, tags, and pagination links. Verified that standard ?limit=3&offset=1 strings were generated and correctly parsed by Express into separate req.query properties.
  3. Automated Unit Test Suite Execution: Ran the automated regression test suite via vitest --run.

3.2 Results and Discussions

3.2.1 Test Results

  • BUG-01 Test Outcome: PASSED. Decoded JWT tokens confirmed payload structure: { username: "israt_jahan", email: "israt@example.com", iat: ... }. Subsequent authenticated API requests succeeded with status 200 OK.
  • BUG-03 Test Outcome: PASSED. Outgoing URLs confirmed single ampersand formatting /api/articles?limit=3&offset=1. Express server parsed req.query.limit = 3 and req.query.offset = 1, enabling smooth pagination.
  • Regression Test Outcome: PASSED. All unit test modules executed with zero errors.

3.2.2 Analysis and Outcome

The empirical verification results confirm that both implemented patches directly addressed the root causes of their respective defects. By passing the full database user model instance in users.js, user authentication claim integrity was restored across all protected routes. By replacing double ampersands in getArticles.js, URI standard compliance was re-established, restoring article pagination and tag filtering functionality.

Chapter 4

Conclusion

4.1 Introduction

This lab project presented an end-to-end Software Quality Assurance audit, exploratory defect discovery, root-cause analysis, production-grade code remediation, and verification testing on the Conduit RealWorld web application.

4.2 Practical Implications

Through this project, several key software engineering and quality assurance takeaways emerged:

  1. Security Token Payload Integrity: Security claims within JWT tokens must always be constructed from verified database model objects rather than unvalidated client request body parameters.
  2. RFC Standard Compliance: Strictly adhering to URI query parameter standards (single & delimiters) prevents silent parameter parsing failures in web servers.
  3. Value of Combined Testing Strategies: Combining static code walkthroughs with exploratory boundary testing exposes critical edge-case flaws that standard automated happy-path tests often miss.

4.3 Scope of Future Work

Future extensions for this SQA audit project include:

  • Refactoring CommentEditor.jsx to wrap state setter calls inside async promise callbacks to prevent premature input clearing on failed posts.
  • Adding strict .trim() sanitization in articles.js controller to reject whitespace-only submissions.
  • Integrating DOMPurify sanitization in Article.jsx markdown renderer to neutralize potential stored XSS threats.
